# AGENTS.md - Orderly CLI

CLI tool for Orderly Network trading. Keys stored in OS keychain — never exposed to AI context. The CLI handles signing internally and returns only results.

Run `orderly --help` for complete command reference. The CLI is self-documenting.

## Critical Gotchas

- **`--account` is always required** for authenticated commands. No default. Use `orderly auth-list` to get account IDs.
- **Hex account IDs must be quoted** in shell: `--account "0x5a6b..."` (unquoted hex is parsed as float).
- **Symbol names must be uppercase**: `PERP_ETH_USDC`, not `PERP_ETH_usdc`.
- **Default output is compact JSON**. Use `--csv` for tabular data. API wrapper `{ success, data }` is auto-unwrapped.
- **`auth-export-key` blocks AI agents**: requires interactive TTY + typing "EXPORT".
- **Orderly Predict uses per-round symbols**: read the symbol from `predict-rounds` / `predict-round`; never construct or reuse one.
- **Predict only accepts LIMIT/IOC/POST_ONLY with `margin_mode=ISOLATED`**: use `predict-buy` / `predict-sell` / `predict-close`, not `order-place` or `positions-close`.
- **DOWN orders are converted to the UP book**: buying DOWN at `d` is `SELL UP @ 1-d`. Use `predict-orderbook` to read `down_asks` / `down_bids`.

## Security Architecture

- **Layer 1 (Wallet)**: EIP-712 (EVM) or Ed25519 (Solana) — for account registration. Wallet keys in OS keychain.
- **Layer 2 (API)**: Ed25519 keypair for trading operations. Auto-generated by `wallet-add-key`. Stored in OS keychain, network-scoped as `accountId:network`.

Keychain backends: macOS Keychain, Windows Credential Manager, Linux libsecret/gnome-keyring.

## Architecture

Rust, single static binary, no Node runtime (the TypeScript implementation was
removed in v2.0.0).

```
src/
├── main.rs               # entry point, clap error mapping
├── cli.rs                # clap command tree (all 80 commands)
├── commands/             # one module per command group
├── api.rs                # REST client, byte-identical signing
├── dex_api.rs            # Orderly One (broker) API
├── contracts.rs          # chain/token metadata (cached)
├── ws.rs                 # WebSocket snapshot
├── crypto.rs             # Ed25519 + base58/base64 + keccak
├── evm.rs                # EIP-712 / personal_sign / parseUnits
├── solana.rs             # keccak+ABI+Ed25519 signing
├── keychain.rs           # Secret Service (keytar-compatible, enumerable on Linux)
├── output.rs             # JSON/CSV rendering, JS-compatible numbers
├── help.rs               # cac-format help text
└── account_select.rs     # Account resolution
```

`tests/parity_*.rs` diff the implementation against fixtures recorded from the
legacy TypeScript CLI; see `parity/README.md`.

npm packaging lives outside `src/`:

```
npm/cli/bin/orderly.js    # @orderly.network/cli entry point (spawns the platform binary)
npm/cli/lib/resolve.js    # platform/arch -> @orderly.network/cli-<os>-<cpu>
scripts/npm-platforms.mjs # packs the launcher + six binary packages for the release job
```

## Build & Quality

```bash
cargo build --release
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

Releasing: push a tag matching `Cargo.toml` (e.g. `v2.0.0`). The release
workflow builds six targets, signs with cosign, attests build provenance and
publishes the release. A separate manual GitLab job, `npm_platforms`, downloads
those six archives and republishes them to npm (`scripts/npm-platforms.mjs`):

- `@orderly.network/cli-<os>-<cpu>` — the binaries, `os`/`cpu` filtered, no `bin`
- `@orderly.network/cli` — the package users install; `bin/orderly` launches the
  platform binary with inherited stdio. Source lives in `npm/cli/` and is
  stamped with the release version by the packer. Published last, after the
  platform packages it depends on.

The repository root package is `@orderly.network/cli-wasm`, the request/signing
layer compiled to WebAssembly (no keychain; the caller supplies a signer). It
is published by the shared npm release template.

npm publishing runs in GitLab because `PUBLIC_NPM_TOKEN` lives there; GitHub has
no npm credential. Run `npm_platforms` on the tag pipeline once the GitHub
release exists. See `INSTALL.md`.

`npm_unpublish_orderly` is a one-off manual job for deleting the retired
`@orderly.network/orderly` name (renamed to `cli-wasm`). It refuses to run
unless the pipeline sets `CONFIRM_UNPUBLISH=@orderly.network/orderly`, and
supports `UNPUBLISH_DRY_RUN=1`. Deletes always target
`UNPUBLISH_REGISTRY` (default `https://registry.npmjs.org/`), never the publish
mirror, and the result is verified with a direct request to the packument.
Remove the job once the package is gone.

## Troubleshooting

- **Linux keychain**: requires a running Secret Service (gnome-keyring / KWallet)
- **401**: API key not registered. Run `wallet-add-key`.
- **403**: Signature invalid/expired. Check system clock.
- **Build errors**: `cargo clean && cargo build --release`
